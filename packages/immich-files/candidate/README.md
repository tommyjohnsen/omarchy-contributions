# Immich Files V7: experimental read-only source/configuration reference

New standalone code is MIT. Reserved endpoint/account/schema constants require private configuration. This is not a generic installer or a verified real-account integration. Frozen reviews and live installations remain unchanged. Schema excerpts derive from Immich v3.3.5 and retain AGPLv3 notices plus the full exact upstream body in UPSTREAM-IMMICH-LICENSE. A fresh official comparison preserves even its final blank line; older complete-body snapshots normalized that line away.

## Installation and behavior

Install immich_files.py, connect_immich_files.py, bounded_curl.py and mount_support.py together. Create the service/helper virtualenv with `python -m venv --system-site-packages ~/.local/share/immich-files/.venv` so system PyGObject/gi and the Secret typelib are visible, then install requirements.txt through that venv Python. Both helper and daemon use that interpreter. A fresh temporary venv with this option successfully imported gi/Secret; no clean full service/account install was tested. System dependencies include curl, FUSE3/fusermount3, GI/libsecret, Secret Service, systemd user session, Linux procfs and a desktop opener. Home must be local/resolvable. The mount parent is resolved in a bounded isolated child, never by realpath on the mounted leaf. This supports an intermediate Pictures symlink without blocking the helper in its target. The unit follows graphical-session.target with a bounded restart budget. The private helper accepts no credential arguments, uses getpass, and requires unique key readback before starting. Missing keys may prompt; locked/duplicate/unloadable/empty existing items fail explicitly rather than being mistaken for missing. A malformed single saved text key may be privately replaced. The validated helper resets failed state before start/restart.

Connection validation shares one25s deadline across album/search/size/range calls and scans at most one PAGE=250 response. It skips zeros before choosing a nonempty original, preserving exact206/Content-Range checks. If no nonempty candidate exists in that bounded page, download capability is unproven; no fabricated capability verification is claimed. Opening an already-verified folder is best-effort xdg-open and cannot invalidate setup.

SearchResponseDto's HTTP body contains assets referencing SearchAssetResponseDto, whose items/nextCursor the parser reads. openapi-v3.3.5-response-envelope.json provides the complete wrapper; the earlier excerpt.response denotes only the nested assets schema. Do not flatten production parsing based on that excerpt. Request filter/orderBy/cursor and UUIDv4 contracts remain pinned to official v3.3.5.

## Boundaries and recovery

Curl config/key travels through stdin; subprocess output/stderr and elapsed time are independently bounded, including HEAD. Strict HTTPS origin and exact Range semantics remain. Secrets are still within the same-user/process trust boundary. Invalid individual metadata rows are skipped/countable; invalid containers and transient/auth failures propagate. Only missing originals skip directory entries. Directory handles retain stable entry snapshots until release. Content reads have one dedicated worker token and24s shared cache/HEAD/download budget; metadata has two tokens and fetches outside its structural lock. Cache downloads stay serialized to preserve capacity. Versioned inodes/no keep_cache avoid retaining old content identity across opens.

The kernel mount table is read with a4MiB cap and strict field/escape parsing before any mounted-leaf probe. Only exact FUSE source Immich may be recovered; foreign mounts are refused. All mounted-leaf lstat/stat/scandir work runs in one isolated child with a responsiveness deadline. Timeout kills the child and spends at most0.5s attempting reap; the helper does not wait indefinitely for an unkillable kernel-blocked child. A timed-out/hung mount is left untouched. A disconnected own mount with an active unit is restarted only after private key validation, rather than unmounted while that service is active. Startup may clean its own disconnected predecessor. The readiness loop is observation-only: mount_record/probe, retrying ENOTCONN/ESTALE/ETIMEDOUT/EIO to an absolute12s budget. It never calls recovery preparation, unmount or service state changes. No redundant raw parent listdir remains. Cleanup/systemd may have their separately documented timeouts.

Unkillable child processes can remain until the kernel operation returns; this design bounds the helper wait, not every kernel resource lifetime. Existing unmounted mount directories must be empty, owned and private; automatic chmod/unconditional unmount is not used. The node cap requires eventual service restart, and the10GiB free-space reserve remains deliberate example policy. ACLs/hostile same-user namespace races, large-library lifecycle and inode reclamation are unverified.

79 generated-data tests passed: API/request/response contracts, core cache/read-only behavior, malformed records, keyring flags/states, helper replacement/readback/restart decisions, deadlines/cancellation/worker availability, stable directory offsets, same-size replacement handles, strict capability probes and optional opener behavior. Explicit fixtures show mode0700 stays0700 under umask022 and simultaneous Trio opens allocate distinct correct handles. Neither disputed static claim justified speculative chmod/handle-lock code.

Four actual disposable generated FUSE fixtures passed: lazy listing/cached byte-correct reads/cursor pages/three rejected mutations; partial enumeration (three files/four callbacks around0.138s); SIGKILL→safe own-stale cleanup→remount; and SIGSTOP responsiveness timeout around0.183s below a Pictures symlink, leaving the hung mount untouched. V7 is a measured incremental parser correction over the exact frozen V6 packets. Kernel records split on LF only; fields split on ASCII space, with empty records/fields refused. Raw CR within a field remains intact. Executed Python bytes.splitlines behavior splits CR/LF but preserves VT,FF and0x85; the latter were overclaimed by an earlier static review. Three added regressions cover those cases. The delta also incorporates the supported V6 desktop findings: read-only transient readiness retries, bounded parent-only resolution, fresh-venv GI guidance and corrected PAGE250 documentation. The core API/transport/cache module is unchanged. DELTA-BASE.json binds complete base file/request hashes; delta.patch covers all changed existing code/tests/fixtures, with full files supplied.

The proc reader uses Python BufferedReader.read(cap+1), not one os.read syscall. An executed short-read RawIOBase fixture wrapped in a real BufferedReader returns the final mount after multiple seven-byte reads and EOF; the model's prefix-loss assertion is not adopted. The4MiB cap and malformed/truncated-table refusal remain. Source code fixtures cover transient stale/slow startup success without any recovery/unmount call, final timeout, foreign identity, parent-alias resolution and parent-resolution timeout.
