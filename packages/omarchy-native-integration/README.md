# Bounded native minimize integration for Omarchy

This separate desktop-policy module consumes `window.minimize` from a patched Hyprland core. It is not part of the Hyprland C++ guard patch and must not load a compatibility bridge. Install only in an isolated test configuration until its release gates pass. Load the file once from that configuration; it registers its event callback and returns a testable handle/status interface.

Codex implemented the bounded queue after actual independent Claude and Grok reviews identified unrestricted helper spawning in the prior reference handler. Those reviews do not constitute approval of this new revision. New standalone code uses MIT under Tommy Johnsen's delegated license choice. Upstream authorship and licenses remain unchanged.

Policy accepts only true requests for mapped windows on positive integer numbered workspaces and validated bounded hexadecimal addresses. It coalesces queued/cooling requests per address. At most 32 total queued plus cooling records exist; overflow is ignored. A global HL one-shot timer drains at most one helper per 100 ms. Each dispatch retains a one-second per-address cooldown, then releases its record. Expired or moved-special windows are skipped before dispatch; invalid entries cannot strand the following valid target. Stored HL.Window userdata holds a weak window reference. Timer deadlines use Hyprland steady time and config reload cancels timers. No os.time or external clock is used.

The helper remains asynchronous. Each dispatch uses the fixed command `/usr/bin/timeout --signal=TERM --kill-after=1s 5s omarchy-hyprland-window-minimize HEX`. GNU coreutils is a normal runtime dependency. No `--foreground` is used: GNU timeout owns the process group, sends TERM after five seconds, and escalates to KILL one second later. Together with globally paced launches this bounds ordinary blocked helper groups to roughly 60 concurrent groups, subject to OS scheduling. The trusted stock helper and ordinary children must stay in that process group; this is not confinement of a user-replaced daemonizing helper, nor a guarantee against uninterruptible kernel tasks. The executable is resolved through the trusted normal Omarchy PATH. Existing helper logic controls the eventual move and restore behavior. Numbered tiled workspaces may be rejected by that helper. False requests deliberately do not restore windows or clear cooldown. Clearing cooldown on false would let a client bypass the launch limit. A closed address reused during cooldown can be delayed by at most the remaining cooldown; a queued expired userdata cannot retarget a newly created window.

Run unit checks with `lua tests/behavior.lua` and `luac -p native-minimize.lua`. The portable runtime harness resolves the sibling native-minimize.lua and hashes the exact bytes it loads. It requires explicitly authorized Wayland/Hyprland IPC access and uses only a disposable nested compositor. Run `python3 runtime/verify.py --hyprland /absolute/path/to/guarded/Hyprland --native-gtk` for the combined native GTK protocol and component checks; without --native-gtk it runs component checks only. It does not edit user configuration. Python GI with GTK3 and Foot are runtime-test dependencies. Only synthetic GTK set_minimized protocol lines are retained; there is no desktop-wide input capture.

The new actual nested run used guarded patched Hyprland 0.57.1, real HL.Window userdata/timers and real stub helper processes. A synthetic native GTK3 window sent exactly one actual Wayland set_minimized request. The core emitted through hl.on with mapped HL.Window and boolean true, and the unchanged policy launched one helper. This closes the callback-signature/native Wayland single-request integration gap. The separate 1000-request resource test still invokes the callback directly, so it is not a native-protocol flood test and does not prove XWayland transport. A 1000-request burst plus a cooldown burst launched one helper; normal retry, multi-window FIFO, closed-window and special-workspace skipping, timer cleanup and config reload passed. Parent geometry was unchanged and original focus restored. Unit tests cover 64 distinct windows, the 32-record cap, and assert the exact timeout wrapper on every command. A TERM-ignoring stub helper parent and blocked sleep child were both no longer running after 6.122 seconds in the isolated nested compositor, exercising the SIGKILL fallback. See runtime/results.json.
