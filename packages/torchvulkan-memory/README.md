# torchvulkan reserved and reusable-cache proposal, V2

Base zainsharief/torchvulkan ab9fd4b82033d29abc5dd03a3d0a9c6058606886 (MIT). Apply backend-memory.patch to that base. Original MIT notice and authorship are retained in LICENSE.MIT. Codex/OpenAI prepared this narrow allocator API contribution and tests for Tommy Johnsen; no backend/kernel authorship is claimed.

memory_reserved and reserved_bytes.all.current now report VMA allocator-owned blockBytes for the selected device's existing VRAM heap selection. Internal memoryUsage/mem_get_info driver-pressure semantics are unchanged. The counter is not an all-heap tensor total or guaranteed reclaimable cache. Existing max_memory_allocated and logical active/allocated peak metrics are unchanged; this base has no max_memory_reserved API.

memory_cached(device=None) resolves the selected/current device, flushes its queued work before taking the cache mutex, then sums exact reusable DEVICE_ONLY buffer-pool bytes. Flush releases the GIL and the existing dispatcher waits for its GPU fence before buffers are inspected. Buffers are reused by exact rounded-size bin, so total cache bytes are not a promise that arbitrary differently sized tensors fit. Staging buffers, live tensors, other devices and other processes are excluded. The query can block for pending work and is a concurrent snapshot, not a memory reservation.

The earlier allocator_unused field, buffer probe and heap compatibility helper are deliberately removed. VMA selects specific memory types using allocation preferences and may prefer dedicated allocations for large tensors. Heap-wide blockBytes minus allocationBytes cannot be advertised as generic DEVICE_ONLY capacity even if every type is permitted. Prior candidate evidence showing an apparent repeated-eviction fix depended on this unsupported assumption and is superseded. No arena capacity API is exposed or consumed here.

Fresh isolated-overlay tests: actual32MiB tensor becomes32MiB cached; empty_cache makes cached0 while VMA retains reserved arena. A64MiB separate GPU process leaves our reserved/cache counters unchanged. pytest passes. Peer check is Linux/POSIX+available-memory guarded, stderr goes to DEVNULL, pipes are closed. The obsolete Vulkan-header fixture was removed along with its unsafe helper. Platform assertions do not assume reserved>=logical allocations across heaps.

Timing rechecked using perf_counter_ns with7batches of10,000calls: median idle memory_cached202.65ns, memory_stats266.39ns on this machine. There is no queued work in those idle numbers. A separate tiny Comfy split-attention benchmark observed96queries/12runs, median9.639ms synchronizing versus9.602ms for a benchmark-only fixed counter control; this is not a production throughput bound. Source context includes the actual vkWaitForFences path.

Only Linux Asahi Apple M3 Pro, Python3.12.16, Torch2.15.0+cpu were executed. Discrete/multiple GPUs, Windows/macOS and arbitrary concurrent workloads remain untested. Comfy cache-only estimates remain conservative after trimming: the actual two-buffer repeat test still over-evicts; no claim that this is fixed is made. A clean full-source packaging build remains a release gate beyond the verified incremental isolated relink. No binary overlays or build caches belong in a release.
